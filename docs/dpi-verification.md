# 모니터별 DPI / 좌표 변환 검증 현황

좌표 변환은 [`src/translator/ui/screen_geometry.py`](../src/translator/ui/screen_geometry.py)에 있습니다. 두 방향이 있습니다.

- 박스(논리) → 캡처(물리)
- OCR 원문 위치(물리) → 번역 말풍선(논리)

이 문서는 **어떤 환경을 어떤 방법으로 확인했는지** 기록합니다. 실제로 확인하지 않은 환경은 "미검증"으로 둡니다.

최종 갱신: 2026-10-10 (말풍선 배치 검증 추가)

## 검증 상태 구분

| 표시 | 뜻 |
| --- | --- |
| ✅ 실측 확인 | 실제 Windows 화면에서 앱이나 캡처를 실행해 확인함 |
| 🟡 시뮬레이션 확인 | 실제 화면이지만 Qt 배율(`QT_SCALE_FACTOR`)로 흉내 낸 환경에서 확인함. Windows 디스플레이 배율 설정과는 다름 |
| 🔵 계산식만 확인 | 가짜 모니터 정보로 변환 계산만 단위 테스트함 |
| ⬜ 미검증 | 확인하지 않음 |

## 시뮬레이션이 실제 환경을 대신하지 못하는 이유

`QT_SCALE_FACTOR`는 Qt 안에서만 배율을 적용합니다. 실제 Windows 배율 환경에서는 다음이 추가로 관여하는데, 시뮬레이션은 이것을 거치지 않습니다.

- 운영체제가 모니터별 DPI를 알려 줌
- 창이 모니터를 넘을 때 `WM_DPICHANGED` 메시지가 옴
- MSS 프로세스의 DPI 인식 설정

따라서 🟡 결과는 "변환 계산과 Qt의 창 배치 규칙이 맞물린다"는 증거일 뿐입니다. 실제 배율 환경에서 맞는다는 보장은 아닙니다.

## 실제 환경에서 확인하는 방법

배율이 다른 모니터가 있는 PC에서 다음을 실행하고 결과를 이 표에 기록합니다.

1. Windows 설정에서 모니터별 배율을 정합니다 (예: 주 모니터 100%, 보조 모니터 150%).
2. 아래 명령을 실행합니다. Qt 배율 대신 Windows 배율이 적용되도록 `QT_SCALE_FACTOR`는 설정하지 않습니다. 이 테스트는 Qt 배율 1.0 경우에서 실제 Windows 배율을 그대로 사용합니다.

   ```bash
   TRANSLATOR_REAL_SCREEN_TESTS=1 pytest tests/test_dpi_real_screen.py
   ```

3. 앱을 실행해 각 모니터에서 영역을 선택하고, 박스 안 내용이 결과 창의 Mock OCR 크기(물리 픽셀)와 맞는지 확인합니다.
4. 박스를 배율이 다른 모니터로 옮긴 뒤 `영역 번역`을 눌러 확인합니다.

## 실제 화면 테스트의 간헐적 멈춤 조사 (2026-10-11)

### 증상

실제 화면 테스트를 반복 실행하면 드물게 하위 프로세스가 끝나지 않았습니다. 그 실행은 `subprocess.run`의 60초 시간 제한에 걸려 69.5초 뒤 실패했습니다.

### 원인

확인한 사실과 추정을 나눠 적습니다.

- **확인한 사실**
  - 다른 테스트를 함께 돌려 부하를 건 반복 실행(40회)에서, MSS의 화면 복사가 1회 일시적으로 실패했습니다 (`ScreenShotError: Windows graphics function failed: BitBlt`).
  - 이 반복 실행에서는 검사 함수에 `try/finally`가 이미 들어가 있었습니다. 그래서 그 실행은 멈추지 않고 "실패"로 끝났습니다.
  - 그 전의 검사 스크립트는 예외가 `QTimer.singleShot`으로 호출된 검사 함수 밖으로 빠져나가면 `app.quit()`를 호출하지 않는 구조였습니다. 이 구조에서는 Qt 이벤트 루프가 끝나지 않아, 프로세스가 시간 제한까지 멈춥니다.
- **추정**: 69.5초 멈춤은 같은 일시 실패가 `try/finally` 없는 구조에서 일어난 것으로 봅니다. 멈춘 그 실행의 스레드 덤프는 남아 있지 않아 직접 확인하지는 못했습니다.

즉, 멈춤의 근본 원인은 **예외가 나면 이벤트 루프를 끝내지 않는 검사 스크립트 구조**로 봅니다. 화면 복사 실패는 그것을 드러낸 계기입니다. 시간 제한은 원인이 아니라 증상을 끊어 준 안전장치일 뿐입니다.

### 조치

- **검사 스크립트**: 검사 함수를 `try/finally`로 감쌌습니다. 예외가 나도 항상 `app.quit()`를 호출하고, 예외는 결과에 기록해 실패로 보고합니다 (멈춤 대신 실패).
- **화면 복사 일시 실패**: 앱의 캡처(`MssScreenCapturer`)와 검사 스크립트가 정해진 횟수(`CAPTURE_TRANSIENT_RETRIES`, 1회)만 다시 시도합니다. 검사 스크립트는 다시 시도한 횟수를 결과(`capture_retries`)에 남깁니다.
- **시간 제한(60초)**: 안전장치로 그대로 둡니다.

### 확인 결과

- 반복 실행: 두 검사 스크립트 × 20회 = 40회를 실행했습니다. 그동안 다른 프로세스에서 offscreen 테스트 293개를 6번 연달아 돌려 부하를 걸었습니다.
  - 결과: 성공 40, 실패 0, 멈춤 0. 가장 긴 실행 1.1초.
- 이번 실행에서는 화면 복사 일시 실패가 한 번도 일어나지 않았습니다 (`capture_retries` 합계 0). 그래서 **재시도 경로는 실제 화면에서 검증되지 않았고**, 가짜 MSS를 쓰는 단위 테스트로만 확인했습니다.
- `TRANSLATOR_REAL_SCREEN_TESTS=1 pytest tests/test_dpi_real_screen.py`: 10개 통과 (QT_SCALE_FACTOR 1~2, 주 모니터 1대 환경).
