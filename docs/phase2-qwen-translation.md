# Phase 2 4단계: Qwen 번역 연결

작성일: 2026-10-12 · 상태: **연결 완료** (기본 모델 Qwen3.5-9B Q4_K_M, 번역 품질은 아직 부족한 부분이 있음)

## 결정 (사용자 결정 포함)

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 실행 방식 | **llama.cpp 서버**(`llama-server`)를 앱이 별도 프로세스로 띄우고, OpenAI 호환 HTTP로 호출 (사용자 결정) | Python 의존성이 늘지 않고(표준 라이브러리만 사용) PaddlePaddle과 CUDA 라이브러리가 한 프로세스에 섞이지 않음. 같은 어댑터로 다른 로컬 서버나 클라우드 API도 연결 가능 |
| 원문 언어 | **영어 → 한국어** (사용자 결정) | 요청의 원문 언어가 `auto`이면 영어로 본다 (`ChatServerSettings.default_source_language`) |
| 모델 | **Qwen3.5-9B Q4_K_M** (비교 후 결정, 사용자 승인) | 아래 비교에서 오역이 가장 적음. 4B(Q8)와 지연·VRAM이 거의 같음. Notion의 초기 후보는 "Qwen3-4B 계열(번역 실험 후 확정)"이었음 |
| 모델 파일 | unsloth가 변환한 GGUF (Qwen 공식 GGUF가 없음) | sha256을 Hugging Face 공개값과 대조함. 원본 가중치 라이선스 Apache-2.0 |
| llama.cpp | 공식 GitHub 릴리스 b11557, Windows CUDA 13.4 빌드 | sha256을 GitHub 공개값과 대조함. 드라이버(CUDA 13.3)에서 GPU로 동작 확인 |

## 앱 구조

```
main ─ select_translator() ─▶ ChatCompletionTranslator ─HTTP(127.0.0.1)─▶ llama-server.exe (GGUF, GPU)
   └─ LlamaServerProcess.start() / stop()   (빈 포트, Job Object, 콘솔 창 없음, 출력 버림)
```

- `adapters/translation/chat_completion.py`: 프롬프트 구성, 출력 검증, 재시도, 서버 준비 대기
- `adapters/translation/llama_server.py`: 서버 프로세스 시작·종료
  - 앱이 비정상 종료되어도 Windows Job Object로 서버가 함께 끝납니다.
- `adapters/translation/factory.py`: 엔진 선택(`TRANSLATOR_TRANSLATION_ENGINE`), 외부 주소 제한
- 번역 엔진 인터페이스(`Translator.translate_batch`)와 파이프라인·UI는 바꾸지 않았습니다. Mock 번역은 `mock`으로 그대로 쓸 수 있습니다.

### 출력을 믿지 않기 위한 장치

| 장치 | 내용 | 계기 (측정) |
| --- | --- | --- |
| JSON 스키마 제약 | 원문 수와 같은 개수의 문자열 배열을 생성 단계에서 강제하고, 받은 뒤 다시 검증 | 묶음 번역의 개수 불일치 방지 |
| 생각 모드 끄기 | `chat_template_kwargs.enable_thinking=false` | Qwen3.5에서 켜면 16줄에 27초 동안 생각만 하다가 출력 한도에 걸림. 끄면 2.2초 |
| 문자 제한 패턴 | 원문에 없던 한자·가나·키릴 문자를 생성 단계에서 막음 | Qwen3.5가 한국어 번역에 "闭嘴" 같은 한자, 키릴 문자를 섞음(9B 형식 재시도 5회). 적용 후 0회 |
| 길이 제한 | 번역문 하나를 가장 긴 원문 글자 수의 2배(최소 40자)로 제한 | 문자열을 끝내지 못하고 30초 넘게 생성한 뒤 서버 오류(500)가 남. 적용 후 6회 반복에서 0회 |
| 줄 단위 재시도 | 번역 언어가 맞지 않는 줄만 따로 한 번 더 번역하고, 그래도 안 되면 그 줄은 원문을 표시 | 실제 바탕 화면 124줄 중 몇 줄(파일 경로 등) 때문에 전체 화면 번역이 통째로 실패함 |
| 한국어 원문 건너뛰기 | 글자의 절반 이상이 한글인 원문은 모델에 보내지 않음 | 바탕 화면의 한국어 UI를 한국어로 다시 번역할 필요가 없음 |
| 재시도 제한 | 형식 오류·서버 오류는 한 번만 다시 시도(`LLM_MAX_RETRIES`) | 무한 재시도 방지 |
| 외부 주소 제한 | `TRANSLATOR_LLM_URL`이 localhost가 아니면 `TRANSLATOR_LLM_ALLOW_REMOTE=1`일 때만 사용 | 화면에서 읽은 원문이 외부로 전송되는 것을 막음 |
| 로그 | 원문·번역문은 남기지 않고 개수, 시간, 토큰 수, 오류 종류만 남김 | 개인정보·저작물 보호 |

## 번역 비교 실험

- 도구: [`tests/benchmark/translation_benchmark.py`](../tests/benchmark/translation_benchmark.py)
- 평가 문장: [`tests/benchmark/translation_eval_en_ko.json`](../tests/benchmark/translation_eval_en_ko.json)
  - 직접 작성한 영어 문장 30개와 참고 번역입니다.
  - 범주: 욕설·강도, 관용구, 중의성, 고유명사, 높임말·반말, UI, 숫자, 감정, 긴 문장, 세계관
- 측정 방식: 같은 프롬프트(예시 4개 포함), 같은 제약으로 잽니다.
  - 한 줄씩 번역: 박스에 대사 한 줄이 있는 경우
  - 30줄 묶음 번역: 전체 화면처럼 텍스트가 많은 경우. 16줄씩 두 요청으로 나뉩니다.
- 환경: RTX 5060 Ti 16GB, llama.cpp b11557 (CUDA 13.4), 문맥 4096토큰, 모든 층 GPU

| 모델 | 파일 크기 | VRAM 증가 | 첫 번역 (로딩 포함) | 한 줄 중앙값 / p95 | 30줄 묶음 | chrF (한 줄 / 묶음) | 오역 수 (한 줄, Claude 판정) |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Qwen3-4B-Instruct-2507 Q8_0 | 4.1GB | 4.9GB | 3.3초 | 271 / 521ms | 5.4~5.7초 | 28.5 / 33.5 | 약 8 |
| Qwen3.5-4B Q8_0 | 4.3GB | 4.7GB | 4.5초 | 282 / 632ms | 4.8~5.4초 | 29.8 / 28.2 | 약 8 |

- **chrF**: 참고 번역 하나와 문자 단위로 겹치는 정도입니다. 맞는 번역도 표현이 다르면 낮게 나오므로 보조 지표로만 봅니다.
- **오역 수**: 의미가 틀리거나 뒤집힌 번역, 영어가 남은 번역을 Claude가 판정한 값입니다. **사람이 다시 검토해야 합니다.**

번역 예 (한 줄씩):

| 원문 | Qwen3-4B-2507 | Qwen3.5-4B | Qwen3.5-9B |
| --- | --- | --- | --- |
| Get out of my way, you idiot! | 너의 길을 떠나라, 어이없는 놈아! | 내 앞을 넘겨봐, 이 멍청아! | 길 좀 비켜, 이 바보야! |
| Shut up and fight! | 그만 말하고 싸우라! | 아니고 싸워! | 입 다물고 싸워! |
| Watch your back. | 뒤를 돌아보세요. | 등 뒤를 조심해. | 뒤를 조심해. |
| This is bullshit, and you know it. | 이건 떨어지지 않아요, 너희가 아는 거야. | 이건 바보같은 소리인데, 너도 안다. | 이건 터무니없는 소리야, 너도 알지. |
| Don't you dare leave me again! | 또 나를 떠나지 마! | 다시 저를 버려버려라니! | 다시 나를 버려라! (의미 반대) |
| Save | 구원 | 저장 | 저장 |

### 해석

- **9B가 가장 낫지만 충분하지는 않습니다.**
  - 욕설·감탄사의 강도는 세 모델 모두 약해졌습니다. 예: "bullshit" → "터무니없는 소리", "Damn it" → "아니".
  - 관용구("Break a leg")는 세 모델 모두 직역하거나 틀렸습니다.
  - Notion의 "번역 원문/출력의 표현 강도와 뉘앙스를 임의로 순화하지 않도록 품질 검증" 기준은 아직 충족하지 못합니다.
- **예시 4개를 넣어도 강도 순화는 줄지 않았습니다.** 4B 기준 chrF는 거의 같았습니다.
- **9B Q4는 지연과 VRAM이 4B Q8과 비슷합니다.** 한 줄 약 0.3초이고, VRAM은 약 0.5GB만 더 씁니다. 그래서 9B를 기본값으로 정했습니다.
- **묶음 번역이 한 줄 번역보다 chrF가 낮은 모델이 있습니다**(Qwen3.5 계열). 묶음 크기(`LLM_BATCH_MAX_LINES`, 16)는 다시 볼 대상입니다.

## 알려진 한계와 다음 과제

| 심각도 | 내용 |
| --- | --- |
| High | **번역 품질**: 욕설·감탄사 강도 순화, 관용구 오역, 의미가 뒤집힌 번역(약 30개 중 4개)이 남음. 더 큰 모델, 프롬프트 개선, 문맥(Phase 4), 전용 번역 모델(Notion 05 후속 연구)을 비교해야 함 |
| High | **전체 화면 번역 지연**: 텍스트가 많으면 모든 묶음이 끝날 때까지(20초) 말풍선이 나오지 않고, 그동안 추론 큐가 막혀 박스 번역도 기다림. 묶음마다 결과를 보내거나 번역을 묶음 단위 작업으로 나누는 개선 필요 |
| Medium | **VRAM**: 번역 모델 약 5.3GB, OCR 약 0.4~0.7GB로 합계 약 6GB(따로 잰 값의 합, 어림값). 게임과 VRAM을 나눠 쓰는 영향은 측정하지 않음 |
| Medium | 앱을 켜면 바로 서버가 모델을 불러와 번역을 쓰지 않아도 VRAM을 차지함 |
| Low | GPU가 없는 PC에서 CUDA 빌드 llama.cpp의 동작(CPU 실행)은 확인하지 않음 |
| Low | 일본어·중국어 원문 번역 품질은 평가하지 않음 (원문 언어 결정: 영어) |
| Low | `LLM_TEMPERATURE`, `LLM_BATCH_MAX_LINES` 등 번역 조정값은 대부분 초기 추정값 |

## 라이선스

- **Qwen3.5-9B / Qwen3.5-4B / Qwen3-4B-Instruct-2507**: Apache-2.0 (Hugging Face 모델 정보)
- **GGUF 변환본**: unsloth가 원본을 양자화한 파일입니다.
- **llama.cpp**: MIT. 배포할 때는 CUDA 런타임 재배포 조건을 포함해 다시 검토합니다.
