# 임의 결정 사항

실험이나 기획서(Notion) 근거 없이 개발 중에 **임시로 정한 값과 동작**을 모아 둔 문서입니다.
값을 바꾸거나 결정을 확정하면 이 문서도 함께 고칩니다. 확정된 결정은 Notion의 `07 | 의사결정 기록`으로 옮깁니다.

- 숫자 값은 모두 [`src/translator/tuning.py`](../src/translator/tuning.py) 한 곳에 있습니다.
- "관련 Notion 항목"은 기획서에 미결정이나 확인할 문제로 적힌 항목입니다.

최종 갱신: 2026-10-26 (구조 변경: 세션 ID와 번역 흐름 분리)

## 1. 조정값

### 자동 감지

| 이름 | 값 | 이렇게 정한 이유 | 다시 볼 시점 | 관련 Notion 항목 |
| --- | --- | --- | --- | --- |
| `AUTO_DETECT_INTERVAL_MS` | 500ms | 대사가 바뀐 뒤 1초 안에 번역이 시작되도록 정함. 표본 캡처 비용은 작음 | 실제 게임에서 FPS 영향과 번역 지연을 잴 때 | 영역 변경 검사 간격, 번역 갱신 속도, 게임 FPS 영향 |
| `AUTO_DETECT_PIXEL_DELTA` | 밝기 차 40 (0~255) | 압축 잡음 같은 작은 흔들림은 무시하고, 글자가 생기거나 사라질 때의 큰 변화만 셈 | 실제 게임·영상으로 오탐과 누락을 확인할 때 | 영역 변경 검사 간격 |
| `AUTO_DETECT_CHANGED_RATIO` | 바뀐 표본 0.5% | 600×80 박스의 22px 글자 한 줄이 옮겨지거나 사라질 때(표본의 약 2%)를 잡는다 | 위와 같음 | 영역 변경 검사 간격 |
| `AUTO_DETECT_SETTLE_SAMPLES` | 1회 | (이전 정책 `ChangeTracker` 전용, 지금 기본값 아님) 바뀐 직후 한 번 더 같은 화면이면 번역 | | |
| `AUTO_OCR_MIN_SAMPLE_GAP` | 표본 2개 | 화면이 계속 바뀌는 동안 OCR 요청을 최대 1초에 한 번으로 제한. 화면이 멈추기를 기다리지 않아 움직이는 배경에서도 OCR이 미뤄지지 않음 | 영상 자막에서 OCR 부하와 지연을 잴 때 | 번역 갱신 속도, 게임 FPS 영향 |
| `AUTO_DETECT_GRID_WIDTH` × `HEIGHT` | 96 × 32 표본 | 작은 글자 변화도 놓치지 않을 정도의 밀도. 계산량이 작음 | 작은 글씨 자막에서 누락이 생길 때 | |
| `AUTO_DETECT_MAX_CONSECUTIVE_FAILURES` | 5회 | 약 2.5초 동안 계속 실패하면 자동 감지를 끔(무한 재시도 방지) | | |
| `CAPTURE_TRANSIENT_RETRIES` × `CAPTURE_RETRY_DELAY_MS` | 1회 × 30ms | 부하 중 화면 복사(BitBlt)가 이유 없이 한 번 실패하는 것이 실제 화면 시험에서 40회 중 1회 관찰됨. 한 번만 다시 시도 | 실제 게임 실행 중 실패율을 잴 때 | |

변화 판단 기준은 처음에 "평균 밝기 차이 6.0"이었습니다. 실제 화면 시험(2026-10-10)에서 큰 박스 안의 작은 글자가 옮겨지거나 사라져도 평균 차이가 6에 못 미쳐 자동 번역이 일어나지 않는 것을 확인했고, 그래서 "바뀐 표본의 비율"로 바꿨습니다.

### 콘텐츠 식별 (Phase 3, 2026-10-26)

모두 초기 추정값이며 실제 게임·영상으로 검증하지 않았다.

| 이름 | 값 | 이렇게 정한 이유 | 다시 볼 시점 |
| --- | --- | --- | --- |
| `CONTENT_DETECT_INTERVAL_MS` | 500ms | 활성 창 확인은 가벼운 Windows API 호출뿐이라 박스 자동 감지(500ms)와 같게 둠 | 실제 게임에서 FPS 영향을 잴 때 |
| `CONTENT_SWITCH_CONFIRM_SAMPLES` | 3회 연속 | 3회 × 500ms ≈ 1초 이상 머물러야 콘텐츠 변경으로 봄. Alt-Tab 중간 화면, 작업 표시줄 클릭, 잠깐 다른 창을 보는 동작으로 세션이 바뀌어 번역이 취소되는 것을 막음 | 전환이 너무 느리거나 너무 자주 흔들린다는 사용 경험이 있을 때 |
| `CONTENT_DETECT_MAX_CONSECUTIVE_FAILURES` | 5회 | 식별이 예외로 5번 연속 실패하면 감시를 끔(무한 재시도 방지) | |
| `REGION_SAVE_DELAY_MS` | 300ms | 박스를 끄는 동안 위치가 바뀔 때마다 디스크에 쓰지 않고 마지막 상태만 한 번 저장(UI 스레드에서 쓰기 횟수를 줄임). 정상 종료와 콘텐츠 전환 때는 기다리지 않고 바로 저장 | 강제 종료로 박스 변경을 잃는 일이 있을 때 |
| `STORAGE_BUSY_TIMEOUT_SECONDS` | 1.0초 | 다른 연결이 DB를 쓰는 중일 때 쓰기를 기다리는 최대 시간. 저장은 UI 스레드에서 하므로 SQLite 기본값(5초)보다 짧게 둠. 넘으면 저장 실패로 처리하고 다음 저장 때 다시 시도 | 앱을 두 개 띄우는 사용이 생기거나 저장 실패 알림이 잦을 때 |

콘텐츠로 보지 않는 프로세스(2026-10-26, 코드 리뷰 반영): 디바운스(약 1초)는 순간 전환만 막으므로, 1초 넘게 열어 두는 시스템·보조 창이 콘텐츠를 바꾸지 못하게 `windows.py`의 `_IGNORED_PROCESS_NAMES`로 제외한다. 대상은 UWP 틀 창(`applicationframehost`), 셸(`explorer`: 작업 표시줄·바탕 화면·Alt-Tab), 시작 메뉴·검색·알림 팝업, 입력기, 잠금 화면, 게임 오버레이(Xbox Game Bar, Steam)다. **프로세스 이름은 알려진 이름이며 이 PC에서 모두 확인하지는 않았다.** 그 결과 파일 탐색기 창은 콘텐츠가 될 수 없다. 실제 게임에서 콘텐츠가 엉뚱하게 바뀌면 목록에 추가한다.

저장소 실패 처리(2026-10-26, 코드 리뷰 반영): SQLite를 열 수 없으면 레지스트리 기반 대체 저장소(`SettingsProfileStore`, 프로필 이름 = 콘텐츠 ID)로 계속 실행해 기존 박스가 사라지지 않게 하고, 다음에 SQLite를 열 수 있으면 모든 프로필을 SQLite로 옮긴다. 지금 모니터 구성에서 화면 밖인 박스는 창으로 만들지 않되 설정은 보존해 저장할 때 함께 쓴다.

저장소: 콘텐츠별 박스는 `%LOCALAPPDATA%\MultimodalTranslator\translator.db`(SQLite, WAL, `synchronous=NORMAL`)에 저장한다. 이전 버전이 레지스트리에 저장한 박스는 첫 실행에 `default` 콘텐츠로 옮기고, 박스가 없는 콘텐츠가 처음 식별될 때 그 콘텐츠가 가져간다(사용자 결정, 2026-10-26).

| `LLM_MAX_OUTPUT_TOKENS_PER_LINE` | 128 | 줄마다 출력 토큰 상한. 넘으면 답이 잘려 형식 오류 | 긴 문단 번역이 잘릴 때 |
| `LLM_OUTPUT_LENGTH_RATIO` × `LLM_OUTPUT_MIN_CHARS` | 2배 × 40자 | 번역문 최대 길이. 문자열을 끝내지 못하고 30초 넘게 생성하는 문제를 막음 (**측정 후 정함**: 적용 후 6회 반복에서 0회) | 정상 번역이 잘리는 사례가 보일 때 |
| `LLM_TEMPERATURE` | 0.2 | 같은 원문에 같은 번역이 나오도록 낮게 둔 초기 추정값 | 번역 품질 실험 때 |
| `LLM_CONTEXT_TOKENS` | 4096 | 16줄 묶음과 지시문·예시가 들어가는 크기 | 문맥(Phase 4)을 넣을 때 |
| `LLM_GPU_LAYERS` | 999 (전부) | 9B Q4 전체를 GPU에 올림 | 게임과 VRAM이 부족할 때 |
| `LLM_SERVER_STOP_TIMEOUT_SECONDS` | 5초 | 종료 시 서버를 기다리는 시간. 넘으면 강제 종료 | |

## 2. 동작 결정

### 기획서에서 미결정이거나 확인할 문제로 남은 항목

- **전체 화면의 범위**: 모든 모니터를 합친 영역을 캡처합니다.
- **전체 화면 버튼 모양**: 아이콘이 정해지지 않아 글자 `전체 화면`으로 둡니다. 기획서의 후보는 scan 계열 아이콘입니다.
- **원문과 번역을 함께 표시할지**: 원문은 화면에 그대로 두고, 번역문만 원문 옆 말풍선으로 보여 줍니다.
- **수동 번역과 자동 번역 전환**: 박스별로 우클릭 메뉴에서 켜고 끄며, 오버레이의 `자동` 버튼은 모든 박스를 한 번에 켜고 끕니다.

### 번역 표시 (2026-10-10 변경)

- **위치 기준**: 번역문의 위치 기준은 항상 OCR이 인식한 원문 텍스트 좌표입니다. 바운딩 박스를 기준으로 놓지 않습니다.
- **배치 순서**: 지정 방향(기본 아래)에 자리가 없으면 반대 방향 → 아래 → 위 → 오른쪽 → 왼쪽 순으로 시도합니다. 어디에도 다 들어가지 않으면 지정 방향 위치를 화면 안으로 당깁니다.
- **박스와의 연결**: 박스마다 색을 정하고(6가지를 차례로 사용), 말풍선 왼쪽 색 띠를 같은 색으로 칠합니다. 전체 화면 결과는 회색입니다.
- **알려진 한계(유지)**: 서로 다른 말풍선끼리(박스와 박스, 박스와 전체 화면, 전체 화면 텍스트끼리) 겹치는 것은 피하지 않습니다.
- **기존 결과 창**: "상태·설정 창"으로 바꿨습니다(사용자 결정). 번역문은 표시하지 않고 다음만 맡습니다.
  - 오류와 "텍스트 없음" 알림
  - 편집 모드에서 "말풍선 배경 불투명도"(이 창 배경에도 함께 적용)와 "전체 화면 번역 위치" 설정 (2026-10-11 이름 변경, 사용자 요청)
- **텍스트 단위**: 엔진이 준 조각(글자·단어·줄·블록)을 줄로, 줄을 대사로 묶습니다. 번역과 위치 추적은 대사 단위로 합니다.
- **말풍선 단위** (2026-10-11 변경, 사용자 요청):
  - 바운딩 박스는 박스마다 말풍선 하나에 그 박스의 번역문을 모두 넣습니다.
    - 원문 위치를 읽는 순서(위 → 아래, 같은 줄은 왼쪽 → 오른쪽)로 넣습니다.
    - 원문이 같은 줄이면(세로로 절반 이상 겹침, `TEXT_LINE_VERTICAL_OVERLAP`) 이어 쓰고, 다른 줄이면 줄을 바꿉니다.
    - 말풍선은 박스 안 원문 전체를 감싸는 범위를 기준으로 놓습니다.
    - 번역을 기다리는 대사는 번역이 올 때까지 빼고 보여 줍니다.
  - 전체 화면은 텍스트가 화면 곳곳에 흩어져 있으므로 원문마다 말풍선을 따로 놓습니다.
  - 한 대사가 여러 줄에 걸쳐 한 대사로 묶인 경우, 번역문은 원문과 어순이 달라 원문의 줄 위치를 옮길 수 없습니다. 그래서 강제로 줄을 나누지 않고 말풍선 너비에 맞춰 줄을 바꿉니다.
- **텍스트 추적과 깜빡임 방지** (2026-10-11 변경):
  - 같은 원문이 가까운 위치(글자 높이의 20배 이내)에 보이면 같은 항목이 이동한 것으로 보고, 다시 번역하지 않고 말풍선만 옮깁니다.
  - 같은 원문이 멀리 떨어져 보이면 다른 문장으로 보고 따로 표시합니다.
  - 같은 자리에 다른 원문이 보이면 내용이 바뀐 것으로 봅니다. 새 번역이 올 때까지 이전 번역을 보여 주지 않습니다(오래된 번역 방지).
  - 같은 자리에서 글자가 늘어나는 중(타자 효과)이면 이전 번역을 유지합니다.
  - 인식 결과에서 빠진 텍스트는 그 자리의 픽셀을 비교해 나눕니다.
    - 픽셀이 그대로면 OCR이 놓친 것으로 보고 번역문을 유지하며 재검사합니다.
    - 픽셀이 바뀌었으면 실제로 사라진 것으로 보고 유예 시간 뒤에 지웁니다.
- **번역 엔진 호출**: 한 화면의 서로 다른 원문을 `translate_batch`로 한 번에 넘깁니다. 같은 원문은 캐시를 씁니다.

### 바운딩 박스 (2026-10-10 변경)

- **박스 개수**: 박스는 여러 개 둘 수 있습니다. ID는 `box-1`, `box-2`...이며, 복원한 박스와 겹치지 않게 발급합니다.
- **모드**: 편집 모드와 잠금 모드를 `편집` 버튼 하나로 바꿉니다(사용자 결정). 편집이 꺼진 상태가 예전의 "잠금"입니다.
  - 편집 모드: 박스가 또렷하게 보이고 이동, 크기 조절, 우클릭 메뉴를 쓸 수 있습니다.
  - 잠금 모드: 박스는 숨기지 않고 흐린 점선으로 남깁니다(사용자 결정). 박스, 말풍선, 상태 창은 클릭을 통과시킵니다.
  - 번역을 실행하면(영역 번역, 자동, 전체 화면) 잠금 모드로 바뀝니다.
- **영역을 추가한 직후**:
  - 잠금 모드였다면 바로 번역합니다.
  - 편집 모드였다면 박스를 더 조정할 수 있게 두고, 편집을 끌 때 번역합니다.
  - 전체 자동 감지가 켜져 있으면 새 박스도 자동 감지로 시작합니다.
- **편집 중 박스를 옮긴 경우**: 편집을 끌 때 자동 감지가 꺼진 박스만 다시 번역합니다. 자동 감지 중인 박스는 감지기가 새 위치를 번역합니다.
- **자동 감지기**: 박스마다 자기 자동 감지기와 표본 스레드를 가집니다. 스레드 풀을 공유하면 박스 하나를 지울 때 다른 박스의 대기 중인 표본까지 지워져 자동 감지가 멈추기 때문입니다.
- **두 모니터에 걸친 박스**: 박스 중심이 있는 모니터의 배율을 씁니다. 배율이 다른 모니터에 걸치면 다른 쪽 모니터 부분이 조금 어긋날 수 있습니다.
- **모니터 분리**: 박스가 화면 밖에 남으면 지우지 않고 주 모니터 안으로 옮깁니다. 설정을 잃지 않기 위해서입니다.
- **좌표 반올림**: 논리 좌표를 물리 좌표로 바꿀 때 Qt의 qRound와 같이 0.5를 0에서 먼 쪽으로 반올림합니다. 검증 현황은 [dpi-verification.md](dpi-verification.md)에 있습니다.

### 전체 화면 번역 (2026-10-11 변경)

- **켜고 끄는 버튼**: `전체 화면`을 누르면 켜지고, 다시 누르면 꺼지며 전체 화면 번역문을 지웁니다.
- **위치 추적**: 켜면 먼저 한 번 인식합니다. 그 결과가 오면 전체 화면 감지기가 1초마다 화면 변화를 확인하고, 바뀌면 그 캡처로 다시 인식해 원문 위치를 갱신합니다.
  - 이동한 텍스트는 다시 번역하지 않고 위치만 바꿉니다.
  - 사라진 텍스트는 정리합니다.
- **중복 방지**: 등록된 박스 안의 텍스트는 그 박스가 맡으므로 전체 화면 인식에서 뺍니다(요청할 때의 박스 위치 기준).
- **결과 없는 박스**: 아직 번역 결과가 없는 박스는 전체 화면을 켤 때 함께 인식합니다. 이때 박스가 비어 있어도 따로 알리지 않습니다.
- **영역 선택 중**: 선택 화면(어둡게 덮은 화면)을 화면 변화로 보지 않도록 전체 화면 감지를 잠시 멈춥니다.
- **연속 캡처 실패**: 전체 화면 감지기가 연속 실패로 멈추면 전체 화면 번역을 끄고 알립니다.

### 자동 감지 (2026-10-11 변경)

- **OCR 요청 시점**: 화면 픽셀이 바뀌면 OCR을 요청합니다. 화면이 멈추기를 기다리지 않고, 계속 바뀌는 동안에는 최소 간격(표본 2개)마다 요청합니다. 그래서 배경이 계속 움직여도 OCR이 영구히 미뤄지지 않습니다.
- **번역 시점**: 대사가 다 나왔는지는 OCR 텍스트로 판단합니다. 같은 텍스트가 두 번 연속 인식되거나 최대 대기 시간이 지나면 번역합니다. 사용자가 직접 요청한 번역은 기다리지 않습니다.
- **중복 번역 판단**: 이미 번역한 원문(정규화 기준)은 다시 번역하지 않습니다. 안정화 판단과 중복 번역 판단은 따로 구현했습니다.
- **수동 번역 기록**: 수동 번역의 결과가 오면 그 캡처의 화면 지문을 자동 감지의 기준 화면으로 기록합니다. 추가 캡처는 하지 않습니다.
  - 그사이 박스가 옮겨졌으면 기록하지 않습니다.
  - 기록은 자동 감지를 껐다 켜도 유지하고, 박스를 옮기거나 크기를 바꾸면 버립니다.
- **OCR 재검사**: 화면 변화가 없어도 다음 경우 다시 캡처해 OCR합니다 (자동 감지 박스와 전체 화면 추적만).
  - 안정되지 않은 텍스트가 있으면 0.4초 뒤
  - 결과가 비었거나 OCR이 놓친 텍스트가 있으면 1.5초부터 두 배씩, 최대 3회
  - 재검사도 OCR 캐시를 씁니다. 픽셀이 완전히 같으면 이전 결과를 재사용하고, 감지 기준 아래의 작은 차이라도 있으면 다시 OCR합니다.

### 처리 파이프라인 (2026-10-11 추가)

- **공통 흐름**: 모든 출처(박스, 전체 화면)가 같은 흐름을 씁니다.
  1. 캡처(또는 자동 감지가 찍은 프레임 재사용)
  2. OCR(공유 캐시)
  3. 표시 모델에 반영(위치 갱신, 안정화)
  4. 안정된 새 원문만 번역
- **식별 정보**: 결과마다 출처 ID(영역), 프레임 ID, 요청 ID, 캡처 시각을 붙입니다.
- **같은 캡처 재사용**: 자동 감지가 찍은 캡처를 OCR까지 그대로 넘겨 다시 캡처하지 않습니다. 같은 캡처 내용(영역 + 픽셀 해시)의 OCR은 결과를 재사용하고, 실행 중이면 합칩니다. 바뀐 화면은 해시가 달라 캐시를 쓰지 않습니다.
- **추론 큐**: OCR과 번역(향후 장면 분석)은 공용 큐 하나에서 실행합니다.
  - 동시 실행 수는 `INFERENCE_MAX_CONCURRENCY`(기본 1)로 제한합니다.
  - 우선순위는 번역 > 사용자 OCR > 자동 OCR > 재검사 > 장면 분석입니다. 이미 실행 중인 작업은 중단하지 않습니다.
  - 자동 감지의 표본 캡처는 GPU를 쓰지 않으므로 이 큐를 쓰지 않습니다.
- **오래된 결과 방지**:
  - 같은 출처·같은 종류의 새 요청은 이전 요청을 취소하고, 이전 요청의 결과는 버립니다.
  - 표시 모델은 이미 반영한 프레임보다 먼저 찍힌 프레임의 결과를 버립니다.
  - 지워진 박스나 꺼진 전체 화면의 결과는 버립니다.
- **사용자 요청 우선**: 사용자가 요청한 OCR이 진행 중이면, 그 출처의 자동 요청이 그 OCR을 취소하지 않습니다.

### PaddleOCR 연결 (2026-10-12 추가)

- **엔진 선택**: 환경 변수 `TRANSLATOR_OCR_ENGINE`(`auto` 기본, `paddle`, `mock`)로 고릅니다. `auto`는 PaddleOCR가 설치되어 있으면 PaddleOCR, 없으면 경고 로그를 남기고 Mock OCR을 씁니다. 기존 Mock OCR과 테스트는 그대로 동작합니다.
- **장치** (2026-10-12 변경, 사용자 결정): GPU가 기본입니다. `TRANSLATOR_OCR_DEVICE=auto`(기본)는 PaddlePaddle GPU 빌드와 NVIDIA GPU가 있으면 `gpu:0`, 없으면 `cpu`를 고르고, 자동으로 고른 GPU에서 모델을 불러오지 못하면 CPU로 한 번 다시 시도합니다. 근거는 [phase2-performance-evaluation.md](phase2-performance-evaluation.md)입니다(GPU가 약 25~30배 빠름).
- **설치 환경**: 프로젝트 `.venv`에 설치합니다(사용자 결정). 선택 의존성은 `ocr`(CPU)과 `ocr-gpu`(GPU, Paddle 공식 인덱스 필요)입니다. PaddlePaddle은 3.2.x로 고정합니다.
- **CPU일 때 전체 화면**: 확인 간격을 늘리고, 켤 때 느리다는 안내를 상태 창에 보여 줍니다(사용자 결정).
- **모델**: PP-OCRv5 mobile 검출·인식 모델. 한 모델로 중국어(간체·번체), 영어, 일본어를 인식합니다. CPU에서 서버 모델보다 빠르기 때문에 골랐습니다. 원문 언어가 기획서에 정해져 있지 않아 이 기본값을 썼으며, 한국어 원문은 `korean_PP-OCRv5_mobile_rec`로 바꿔야 합니다.
- **문서용 단계 끄기**: 화면 텍스트는 똑바로 놓여 있으므로 문서 방향 분류, 문서 펴기, 줄 방향 분류를 끕니다(지연 감소). 세로쓰기·기울어진 텍스트는 인식이 떨어질 수 있습니다.
- **CPU 가속(oneDNN) 켬** (2026-10-12 변경):
  - PaddlePaddle 3.3.1에서 oneDNN을 켜면 검출 모델 실행 중 `ConvertPirAttribute2RuntimeAttribute not support` 오류가 나는 것을 이 PC에서 확인했습니다. 그래서 3.2.x로 고정하고 oneDNN을 켭니다(약 5배 빠름).
  - 3.3.x가 설치되어 있으면 자동으로 끄고 경고를 남깁니다.
  - oneDNN은 `cpu_threads`를 따르지 않으므로, paddle을 가져오기 전에 `OMP_NUM_THREADS`를 정해 스레드 수를 제한합니다.
- **모델 불러오기 시점**: 프로그램 시작 때가 아니라 처음 인식할 때 추론 큐의 워커 스레드에서 불러옵니다(UI 스레드 블로킹 방지). 그래서 첫 OCR이 몇 초 늦습니다. 불러오지 못하면(설치 안 됨, 다운로드 실패) 해결 방법을 상태 창에 보여 주고, 다시 시작할 때까지 다시 시도하지 않습니다(무한 재시도 방지).
- **결과 단위와 검증**: PaddleOCR의 줄 결과를 줄 단위(`LINE`) 조각으로 넘기고, 대사로 묶기는 기존 규칙을 씁니다. 필드가 없거나 개수가 맞지 않으면 오류로 처리하고, 빈 텍스트·범위 밖 점수·이미지 밖 위치는 버립니다. 인식 점수는 `TextSegment.confidence`에 담지만 보정된 확률로 쓰지 않습니다.
- **취소**: PaddleOCR 추론은 중간에 멈출 수 없어 추론 전후에만 취소를 확인하고, 추론 중에 취소된 요청은 끝난 뒤 결과를 버립니다. 엔진은 한 번에 한 호출만 실행합니다.
- **네트워크**: 처음 실행할 때만 모델을 내려받습니다(`%USERPROFILE%\.paddlex\official_models`). 가져올 때마다 하는 모델 저장소 연결 확인은 끕니다(`PADDLE_PDX_DISABLE_MODEL_SOURCE_CHECK`). 화면 내용은 전송하지 않습니다.
- **멈출 수 없는 추론이 남았을 때의 종료** (2026-10-12, 실제 화면 테스트에서 발견): 종료할 때 실행 중인 추론을 `SHUTDOWN_TIMEOUT_MS`(3초)까지 기다립니다. 그래도 끝나지 않으면 설정 저장(sync)과 로그 기록을 마친 뒤 기다리지 않고 프로세스를 끝냅니다(`os._exit`). 스레드 풀 정리가 CPU 전체 화면 OCR(30초 이상)을 끝까지 기다려, 창이 닫힌 뒤에도 프로세스가 약 25초 남는 문제가 있었기 때문입니다. 그 뒤에 끝난 작업의 결과는 버립니다.
- **라이선스**: paddleocr, paddlepaddle, paddlex 패키지와 PP-OCRv5 mobile 검출·인식 모델 모두 Apache-2.0입니다(설치된 패키지 정보와 모델 README에서 확인). 배포 전에 의존 패키지 전체를 다시 검토합니다.

### 구조 변경: 콘텐츠·세션 ID와 번역 흐름 분리 (2026-10-26 추가)

Notion 06·05의 Phase 3~5(콘텐츠 식별, 문맥 기억, 선택적 장면 분석)를 붙이기 전에, 모든 기능이 기대는 두 곳을 먼저 바꿨습니다 (사용자 요청).

**1. 콘텐츠·세션 ID가 처리 흐름을 따라 흐름**
- `core/session.py`의 `SessionContext(content_id, session_id)`: 무엇을 보는지(콘텐츠)와 언제부터 언제까지인지(세션).
  - 콘텐츠를 식별하지 못한 동안은 `default`입니다. 같은 콘텐츠도 다시 시작하면 새 세션입니다.
- `TranslationController`가 요청한 시점의 세션을 결과(`OcrResult.session`, `TranslationOutcome.session`)에 실어 보냅니다.
- 세션이 바뀌면(`begin_session`) 진행 중인 요청을 모두 취소하고 늦게 도착하는 결과를 버립니다.
- 흐름은 결과의 세션이 지금 세션과 다르면 한 번 더 버립니다. 세션을 모르는 결과(`None`)는 버리지 않습니다.
- `TranslationWorkflow.change_session`·`change_content`: 이전 세션의 요청·예약·표시를 지우고, 자동 감지 박스와 전체 화면은 현재 화면을 새 세션에서 바로 다시 인식합니다. 수동으로 번역한 박스는 다시 번역하지 않습니다.
- 로그에는 세션 ID만 남기고 콘텐츠 ID는 남기지 않습니다.

**2. 흐름 로직을 UI 계층 밖으로 분리**
- `application/workflow.py`의 `TranslationWorkflow`가 출처별 OCR 요청 방식(수동·자동·조용히), 안정화 뒤 번역 요청과 중복 방지, 재검사 예약, 전체 화면 추적, 세션 전환을 맡습니다.
- `ui/coordinator.py`는 702줄에서 382줄로 줄었고, 버튼·편집 모드·영역 선택·설정 저장·창 위치만 맡습니다.
- 화면과는 인터페이스(`BoxPort`, `DisplayPort`)와 시그널로만 대화합니다. 박스 쪽은 `RegionBoxPort`, 말풍선 쪽은 `TranslationOverlay`가 구현합니다.
- 계층 규칙(core·application은 ui와 Qt 위젯을 가져오지 않음)을 `tests/test_architecture.py`가 검사합니다.
- 동작은 바꾸지 않았습니다. 기존 테스트 415개가 접근 경로 수정만으로 모두 통과했고, 실제 화면(PaddleOCR GPU + Qwen)에서도 같은 시나리오가 통과했습니다.
  - 흐름이 `coordinator._controller` 같은 내부 이름을 쓰던 테스트는 `coordinator.workflow.controller` 같은 공개 경로로 옮겼습니다.
- 전체 화면을 켜는 동안 생기는 박스 요청을 조용히 처리하는 규칙은 `quiet_box_requests()` 블록으로 옮겼습니다.

**아직 하지 않은 것 (Phase 3~4에서)**
- 콘텐츠를 실제로 식별하는 기능과 `change_content`를 부르는 화면 동작은 없습니다.
- 번역 결과 캐시(`TranslationPipeline`)와 OCR 캐시는 아직 콘텐츠·세션과 무관하게 공유합니다. 문맥 없는 번역에서는 문제없지만, 문맥 기억이 들어오면 캐시 키에 콘텐츠와 문맥을 넣어야 합니다.

### 알려진 한계

- **말풍선 겹침**: 서로 다른 텍스트의 말풍선끼리 겹치는 것은 피하지 않습니다.
- **구형 Windows의 캡처 제외**: Windows 10 2004 미만에서는 캡처 제외가 동작하지 않아 번역 말풍선이 다시 캡처·OCR될 수 있습니다.
- **실제 OCR 검증 범위** (2026-10-12): 실제 화면에 띄운 가짜 대사 창으로 다음을 확인했습니다.
  - 확인함: 타자 효과(부분 번역 없음), 대사 교체, 원문 이동, 화자 이름과 대사 분리, 전체 화면의 박스 제외
  - 아직 확인하지 않음: 실제 게임·영상 화면, OCR 오인식으로 글자가 흔들리는 경우의 안정화, 실제 OCR 누락률에 맞는 재검사 간격, 게임 FPS 영향
- **첫 OCR 지연**: 모델을 처음 인식할 때 불러오므로 첫 번역이 몇 초 늦고(실측 3.5~3.8초), 그동안 추론 큐의 다른 작업도 기다립니다.
- **CPU 전체 화면 OCR** (2026-10-12): 개선 뒤에도 실제 화면 한 번에 약 6.5초가 걸리고 코어 4개를 씁니다. 그동안 박스 OCR·번역이 기다립니다. GPU는 약 1.5초입니다.
- **실행 중 GPU → CPU 대체**: 자동으로 고른 GPU에서 모델을 불러오지 못해 CPU로 바뀐 경우, 전체 화면 확인 간격과 안내는 시작할 때의 판단(GPU)을 그대로 씁니다. 로그에 경고가 남습니다.
- **`OMP_NUM_THREADS` 공유**: PaddleOCR 스레드 제한을 위해 프로세스 환경 변수를 정하므로, 같은 프로세스에서 나중에 불러오는 라이브러리(예: 4단계에서 CPU로 실행하는 번역 모델)도 영향을 받을 수 있습니다.
- **`ocr-gpu` 설치 명령**: 이 PC에서는 공식 CDN에서 받은 파일로 설치했습니다. README의 `--extra-index-url` 명령으로 처음부터 설치하는 과정은 직접 확인하지 않았습니다(공식 인덱스 내려받기가 멈추는 문제를 겪음).
- **GPU 경합**: 게임 렌더링과 OCR·번역이 GPU를 나눠 쓰는 영향은 측정하지 못했습니다. OCR과 번역을 합친 VRAM은 약 6GB입니다(따로 잰 값의 합, 어림값).
- **번역 품질** (2026-10-12): 욕설·감탄사 강도 순화, 관용구 오역, 의미가 뒤집힌 번역이 남아 있습니다(평가 30문장 중 약 4개 오역, Claude 판정). Notion의 "표현 강도를 임의로 순화하지 않음" 기준은 아직 충족하지 못합니다.
- **세션 전환 뒤 박스 상태**: 세션이 바뀌면 진행 중이던 수동 박스 요청은 취소되지만 박스의 처리 상태 기록(`RequestStatus.PENDING`)은 그대로 남습니다. 지금은 화면에 보이지 않는 진단용 값입니다.
- **전체 화면 번역 지연**: 실제 바탕 화면 124줄에 20초가 걸렸고, 그동안 추론 큐가 막혀 박스 번역도 기다립니다. 모든 묶음이 끝나야 말풍선이 나옵니다. 4단계에서 Qwen이 같은 GPU를 쓰면 VRAM 합계와 동시 실행 수를 다시 봐야 합니다.
- **같은 픽셀의 재검사**: 같은 픽셀이면 OCR 캐시를 쓰므로, 결과가 실행마다 달라지는(비결정적) OCR 엔진에서는 재검사 효과가 줄어듭니다.
- **실행 중인 추론**: 추론 큐는 실행 중인 작업을 중단하지 않습니다. 긴 OCR이 실행 중이면 번역은 그 작업이 끝난 뒤 시작합니다.

- **복원 조건**: 저장된 창이나 박스의 중심이 지금 연결된 모니터 위에 있을 때만 복원합니다. 값이 손상되었거나 ID가 겹치거나 저장 형식 버전이 다르면 무시합니다.

### 캡처

- **창 제외**: 오버레이, 박스, 상태 창, 말풍선은 Windows 캡처 제외 기능으로 캡처 이미지에 찍히지 않습니다. 번역문이 다시 OCR되는 것을 막기 위해서입니다. Windows 10 2004 이상에서만 동작하고, 실패하면 경고 로그만 남깁니다.
- **캡처 제외가 실패하면**:
  - 박스 테두리 여백은 캡처 영역 밖이라 찍히지 않습니다.
  - 편집 모드의 박스 이름표와 박스 안쪽에 놓인 말풍선은 캡처될 수 있습니다.
