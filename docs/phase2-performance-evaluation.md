# Phase 2 3단계: PaddleOCR 성능 평가

작성일: 2026-10-12 · 상태: **완료** (권장 사항 1·2·5 적용, 아래 "적용 결과")

2단계 실제 화면 테스트([phase2-real-screen-test.md](phase2-real-screen-test.md))에서 CPU 전체 화면 OCR이 30초 이상 걸리고 CPU를 포화시키는 것을 확인했습니다. 이 문서는 그 해결 방안의 후보를 같은 입력으로 비교한 결과입니다.

## 방법

- **도구**
  - [`tests/benchmark/ocr_benchmark.py`](../tests/benchmark/ocr_benchmark.py): 지연, 정확도, CPU, VRAM
  - [`tests/benchmark/contention_benchmark.py`](../tests/benchmark/contention_benchmark.py): 게임 영향 대리 측정
- **입력**: 정답을 아는 합성 화면을 씁니다. 실제 바탕 화면은 개인정보 문제가 있고, 설정마다 같은 화면을 다시 만들 수 없기 때문입니다. 이미지는 저장하지 않았습니다.

| 장면 | 크기 | 내용 |
| --- | --- | --- |
| `box_ja` | 860×170 | 게임 대사 창: 그라데이션, 반투명 패널, 외곽선 일본어 두 줄, 화자 이름 |
| `box_en` | 860×170 | 같은 창에 긴 영어 한 줄 (56글자) |
| `monitor` | 1920×1080 | 바탕 화면 모양의 모니터 한 대. 창 패널 4개, 57줄 |
| `desktop` | 3840×1080 | 모니터 두 대. 창 패널 7개, 116줄 (그중 14px 이하 59줄) |

- **경로**: 앱의 `PaddleTextRecognizer`(입력 변환·출력 검증 포함)를 그대로 거칩니다. 한 번 예열한 뒤 2~5회 잰 중앙값입니다.
- **정확도**:
  - 정답 줄마다 겹치는 인식 줄과의 문자 유사도를 구합니다(공백 무시).
  - "작은 글자 재현율"은 14px 이하 줄 중 유사도 0.8 이상으로 읽은 비율입니다.
- **환경**:
  - CPU: 논리 코어 20개. GPU: RTX 5060 Ti 16GB (측정 중 다른 프로그램이 VRAM 약 7.5GB를 사용 중)
  - PP-OCRv5 mobile 검출·인식 모델(따로 적은 경우 제외)
  - 측정용 가상환경은 프로젝트 밖(scratchpad)에 따로 만들었습니다. 프로젝트 `.venv`는 바꾸지 않았습니다.
    - paddle 3.2.2 CPU: PyPI
    - paddlepaddle-gpu 3.3.1 cu129: Paddle 공식 CDN(`paddle-whl.cdn.bcebos.com`, 810MB) + NVIDIA CUDA 런타임 PyPI 패키지

> **합성 화면의 한계**: 실제 바탕 화면(2단계)에서 기준 설정의 전체 화면 OCR은 33~41초였고, 합성 `desktop`은 20초였습니다. 실제 화면은 글자가 더 많아 대략 **1.7~2배** 더 걸린다고 보면 됩니다(어림값). 실제 게임 글꼴·효과에서의 정확도는 검증하지 않았습니다.

### 해석

1. **시간의 대부분은 인식 단계입니다.** 검출 입력을 줄여도 거의 빨라지지 않습니다(전체 화면 20.2초 → 15.7초). 시간이 줄 수에 비례합니다(모니터 57줄에 약 10초, 줄당 약 170ms). 1280까지 줄이면 작은 글자를 놓칩니다.
2. **oneDNN이 CPU 속도를 좌우합니다.** 같은 3.2.2에서 켜면 약 5배 빠릅니다. 3.3.1에서는 켜면 오류가 나므로(1단계에서 확인), CPU에서 oneDNN을 쓰려면 3.2.x를 써야 합니다.
3. **oneDNN의 스레드 수는 `OMP_NUM_THREADS`로만 제한됩니다.** 4개로 제한해도 박스 지연은 거의 같고(0.15초) 전체 화면은 4초입니다.
4. **GPU가 압도적입니다.** 현재 기본 대비 박스는 약 25배, 전체 화면은 약 31배 빠르고 CPU를 1코어만 씁니다. RTX 5060 Ti(Compute Capability 12.0)에서 정상 동작했습니다.
5. **서버 모델은 쓸 이유가 없습니다.** 느리고 VRAM을 6GB 넘게 쓰며, 이 합성 화면에서는 작은 글자를 오히려 덜 읽었습니다.
6. **실제 바탕 화면 전체 화면 OCR 어림값**(합성 결과 × 1.7~2): GPU 약 1.1~1.3초, CPU + oneDNN 약 7~8초, 현재 기본 33~41초(실측).

## 결과: 게임 영향 대리 측정 (실측, 참고값)

- **가짜 게임**: 60fps 루프에서 작업 스레드 6개가 프레임마다 행렬 곱을 합니다. OCR 없이 프레임 작업 약 8ms입니다.
- **비교 방법**: 다른 프로세스에서 OCR을 쉬지 않고 돌리는 동안, 프레임 작업 시간 중앙값이 얼마나 늘었는지 봅니다.
- **순서 효과 제거**: OCR 없음 → OCR 있음 → OCR 없음 순서로 재고 앞뒤 평균과 비교합니다. 처음에는 앞만 재서, 부하가 이어질 때 CPU 클럭이 떨어지는 효과가 섞였기 때문입니다.

| OCR 설정 (계속 실행) | 프레임 작업 증가 | 반복 측정 |
| --- | --- | --- |
| 현재 기본, 박스 | +31% | |
| 현재 기본, 전체 화면 | +25% | +31% |
| CPU + oneDNN (스레드 제한 없음), 전체 화면 | +36% | |
| CPU + oneDNN + `OMP_NUM_THREADS=4`, 전체 화면 | +34% | +17% (OCR을 멈춘 뒤 원래 값으로 돌아오지 않아 잡음이 섞임) |
| CPU + oneDNN + `OMP_NUM_THREADS=4`, 박스 | +34% | |
| GPU, 전체 화면 | +6% | +6% |
| GPU, 박스 | +11% | |

- **CPU OCR**: 설정과 관계없이 게임의 CPU 작업이 대략 **20~35%** 느려졌습니다. 스레드를 4개로 줄여도 뚜렷이 나아지지 않았습니다. 코어를 나눠 쓰는 것 외에 캐시·메모리 대역폭·전력 한도를 함께 쓰기 때문으로 추정합니다.
- **GPU OCR**: CPU 쪽 영향이 **약 6~11%**로 작습니다.
- **측정하지 못한 것**: 게임 렌더링과 OCR이 GPU를 나눠 쓰는 영향은 이 측정으로 알 수 없습니다. 실제 게임에서 따로 확인해야 합니다.
- 이 측정에서는 어느 설정도 프레임 한도(16.7ms)를 넘기지 않았습니다. 하지만 원래 프레임 작업이 13ms 이상인 무거운 게임이라면 +30%로 한도를 넘깁니다.
- 측정마다 ±10%p 정도 흔들립니다. 실제 게임 FPS 측정을 대신하지 못합니다.

## 적용 결과 (2026-10-12, 사용자 결정: GPU 기본 + CPU 개선, CPU 전체 화면은 간격 늘리고 알림)

- **버전 통일**
  - GPU 빌드 3.3.1 대신 **3.2.2**(cu129)를 씁니다. GPU와 CPU(oneDNN) 경로를 버전 하나로 쓰기 위함입니다.
  - 3.2.2 GPU를 따로 재 보니 박스 33ms, 전체 화면 662ms로 3.3.1과 같았습니다.
  - 같은 GPU 빌드에서 CPU 장치 + oneDNN + 스레드 4개도 동작했습니다(박스 160ms, 전체 화면 4.1초).
- **장치 자동 선택**: `TRANSLATOR_OCR_DEVICE=auto`(기본)는 GPU 빌드와 NVIDIA GPU가 있으면 `gpu:0`, 아니면 `cpu`를 고릅니다.
  - GPU 확인은 paddle을 가져오지 않고 NVIDIA 드라이버에 장치 수만 묻습니다(약 80ms, 시작할 때 한 번).
  - 자동으로 고른 GPU에서 모델을 불러오지 못하면 CPU로 한 번 다시 시도합니다.
- **CPU 경로**
  - oneDNN을 기본으로 켭니다. 오류가 알려진 3.3.x가 설치되어 있으면 자동으로 끄고 경고를 남깁니다.
  - 스레드 수는 `PADDLE_OCR_CPU_THREADS`(4)입니다. paddle을 가져오기 전에 `OMP_NUM_THREADS`를 정하며, 사용자가 정한 값이 있으면 그대로 둡니다.
- **CPU일 때 전체 화면**: 확인 간격을 `FULLSCREEN_DETECT_INTERVAL_CPU_MS`(5초, 초기 추정값)로 늘리고, 켤 때 상태 창에 안내를 보여 줍니다.
- **프로젝트 `.venv`**: CPU용 `paddlepaddle 3.3.1`을 지우고 `paddlepaddle-gpu 3.2.2`를 설치했습니다.

모든 시나리오가 통과했습니다(박스 수동 번역, 타자 효과 부분 번역 0회, 대사 교체, 원문 이동, 전체 화면, 모델 로딩 중 종료).

## 남은 확인 사항

- 실제 게임·영상 화면에서의 정확도(장식 글꼴, 움직이는 배경)와 실제 FPS 영향
- GPU에서 게임 렌더링과 OCR이 경합하는 영향
- Qwen을 붙였을 때의 VRAM 합계와 GPU 동시 실행 수(`INFERENCE_MAX_CONCURRENCY`)
- 첫 실행 때 모델 다운로드 시간(이번 측정은 이미 내려받은 상태)
