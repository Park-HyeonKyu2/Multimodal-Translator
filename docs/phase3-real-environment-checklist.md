# Phase 3 실제 환경 확인 체크리스트

작성일: 2026-11-01 · 대상: 콘텐츠 자동 식별, 콘텐츠별 박스(SQLite)

자동 테스트와 임시 DB로는 확인했지만 **실제 게임, 사용자 PC의 첫 실행, 전체 화면 독점 모드**는 확인하지 못했습니다. 아래 순서대로 직접 확인하고 결과를 표시해 주세요. 위에서부터 순서대로 하는 것을 권합니다 (A → B가 데이터를 바꿉니다).

현재 상태(2026-11-01 확인): `translator.db`는 아직 없고, 레지스트리(`HKCU\Software\MultimodalTranslator\MultimodalTranslator\profiles\default\regions`)에 **이전 방식의 박스가 2개** 있습니다. 첫 실행에서 이 2개가 SQLite로 옮겨집니다.

## A. 준비 (한 번만)

- [ ] **A1. 설정 백업.** 첫 실행은 레지스트리의 기존 박스를 SQLite로 옮기고 레지스트리 값을 지웁니다. 되돌릴 수 있게 먼저 내보내 둡니다.

  ```bash
  MSYS_NO_PATHCONV=1 reg export 'HKCU\Software\MultimodalTranslator' "$USERPROFILE/Desktop/mt-settings-backup.reg" /y
  ```

  PowerShell이나 명령 프롬프트라면: `reg export "HKCU\Software\MultimodalTranslator" "%USERPROFILE%\Desktop\mt-settings-backup.reg" /y`
- [ ] **A2. 어떤 콘텐츠가 기존 박스를 가져갈지 정하기.** 기존 박스 2개는 **앱을 켠 뒤 약 1초 동안 맨 앞에 있는 프로그램**이 가져갑니다(박스가 없는 첫 콘텐츠). 터미널에서 앱을 켜면 터미널이 가져가므로, **앱을 켜고 1초 안에 박스를 쓰려던 게임(또는 브라우저) 창을 클릭해 앞으로 가져오세요.**
- [ ] **A3. 실행.**

  ```bash
  .venv/Scripts/python -m translator.main
  ```

## B. 첫 실행과 기존 박스 이전

- [ ] **B1.** 앱을 켜고 A2대로 게임 창을 앞으로 가져옵니다. 박스 2개가 **사라지지 않고** 보입니다. 첫 실행에서는 시작 직후 옮겨진 박스가 바로 보이고, 약 1초 뒤 콘텐츠가 정해질 때 한 번 다시 그려지는(깜빡이는) 것이 정상입니다. 이후 실행에서는 콘텐츠가 정해지는 약 1초 동안 박스가 안 보이다가 나타납니다.
- [ ] **B2.** 로그(`%LOCALAPPDATA%\MultimodalTranslator\logs\translator.log`)에 `이전 방식의 박스 2개를 SQLite로 옮겼습니다`와 `콘텐츠 변경 확정` 줄이 있습니다.
- [ ] **B3.** DB 내용 확인. 앱이 켜진 채로 실행해도 됩니다 (읽기 전용이라 파일을 만들거나 바꾸지 않습니다).

  ```bash
  .venv/Scripts/python -c "import sqlite3,os,pathlib as P;p=P.Path(os.environ['LOCALAPPDATA'])/'MultimodalTranslator'/'translator.db';c=sqlite3.connect(p.as_uri()+'?mode=ro',uri=True);print(c.execute('select content_id,count(*) from region group by content_id').fetchall())"
  ```

  기대: `[('app:<게임 실행 파일>.exe', 2)]` 한 줄 (`default`는 없음).
- [ ] **B4. 잘못된 콘텐츠가 가져간 경우** (예: `app:windowsterminal.exe`로 나옴): 앱을 끄고 `translator.db`, `translator.db-wal`, `translator.db-shm`을 삭제한 뒤 A1의 백업 파일을 더블클릭해 가져오고(레지스트리 복원) A2부터 다시 합니다.

## C. 콘텐츠 전환 (게임 A ↔ 브라우저)

- [ ] **C1.** 게임 A에서 박스가 보이고 번역이 됩니다.
- [ ] **C2.** 브라우저(또는 다른 프로그램)를 앞으로 가져와 **약 1초 기다리면** 게임 A의 박스와 말풍선이 사라집니다.
- [ ] **C3.** 브라우저에서 박스를 하나 만들면 그 박스는 브라우저에서만 보입니다. 게임 A로 돌아가면 게임 A의 박스만 보이고 브라우저의 박스는 보이지 않습니다.
- [ ] **C4.** 게임 A로 돌아오면 원래 박스(위치·방향·자동 감지 상태)가 그대로 복원됩니다. 자동 감지 박스는 현재 화면을 다시 인식해 번역합니다.
- [ ] **C5.** 전환 직후 이전 콘텐츠의 번역문이 새 콘텐츠 화면에 잠깐이라도 나타나지 않습니다.

## D. 잠깐 스치는 전환은 무시

- [ ] **D1.** Alt-Tab으로 다른 창에 **0.5초 이내**로 잠깐 갔다가 돌아옵니다. 박스와 말풍선이 그대로 유지됩니다.
- [ ] **D2.** 앱의 오버레이 버튼(편집, 영역 추가 등)을 눌러도 콘텐츠가 바뀌지 않습니다 (박스가 사라지지 않음).

## E. 시스템·보조 창은 콘텐츠를 바꾸지 않음 (게임 실행 중, 각각 5초 이상 유지)

이 항목의 프로세스 이름은 알려진 이름이며 이 PC에서 확인하지 못했으므로 **가장 가치 있는 확인**입니다.

- [ ] **E1.** Win 키로 시작 메뉴를 열고 검색어를 입력합니다.
- [ ] **E2.** 작업 표시줄을 클릭하거나 바탕 화면을 보이게 합니다.
- [ ] **E3.** Alt-Tab 화면을 5초 이상 띄워 둡니다.
- [ ] **E4.** Steam 오버레이(Shift+Tab)와 Xbox Game Bar(Win+G)를 엽니다. 쓰지 않으면 건너뜁니다.
- [ ] **E5.** 한글 입력 후보 창이나 이모지 패널(Win+.)을 엽니다.

기대: 모두 박스와 말풍선이 **그대로 유지**됩니다. 하나라도 박스가 사라지면 그 순간 앞에 있던 창의 **프로세스 이름**을 적어 주세요 (작업 관리자 → 세부 정보 탭). 제외 목록(`_IGNORED_PROCESS_NAMES`)에 추가하면 됩니다.

## F. 전체 화면 독점 모드

- [ ] **F1.** 독점 전체 화면으로 게임을 실행하면(창 모드가 아닌) 로그에 `콘텐츠 변경 확정`이 찍혀 게임이 식별됩니다.
- [ ] **F2.** 독점 모드에서 게임 ↔ 바탕 화면을 오가도 박스가 게임 콘텐츠에 맞게 바뀝니다.

오버레이와 말풍선이 독점 모드 위에 보이는지는 이번 확인 대상이 아닙니다 (기존에도 확인하지 못한 항목). 보이지 않으면 별도 문제로 적어 주세요.

## G. 종료 후 복원

- [ ] **G1.** 오버레이 ✕로 종료하고 다시 켭니다. 켠 직후 약 1초 뒤, 앞에 있는 프로그램의 박스가 복원됩니다 (게임 앞이면 게임의 박스, 브라우저 앞이면 브라우저의 박스).
- [ ] **G2.** 강제 종료(작업 관리자에서 종료)했을 때, 마지막 변경 후 0.3초가 지났다면 박스 변경이 남아 있습니다.

## H. 선택 항목

- [ ] **H1. 모니터 분리.** 보조 모니터에 둔 박스가 있는 상태에서 모니터를 분리하고 앱을 다시 켭니다. 그 박스는 보이지 않지만 DB에서는 사라지지 않습니다 (B3 명령으로 개수 확인). 모니터를 다시 연결하고 앱을 켜서 그 콘텐츠로 전환하면 복원됩니다.
- [ ] **H2. 관리자 권한 프로그램.** 관리자 권한으로 실행한 프로그램을 앞으로 가져와도 앱이 멈추거나 오류를 내지 않고, 콘텐츠도 바뀌지 않습니다 (식별 실패 시 현재 콘텐츠 유지).
- [ ] **H3. 파일 탐색기.** 파일 탐색기 창은 콘텐츠로 인식되지 않으므로 앞으로 가져와도 박스가 그대로 유지됩니다 (설계상 한계).

## 문제가 있을 때 알려 주실 정보

| 증상 | 알려 주세요 |
| --- | --- |
| 박스가 엉뚱한 때 사라짐 | 그때 앞에 있던 창의 프로세스 이름, 얼마나 오래 앞에 있었는지 |
| 박스가 사라진 채로 돌아오지 않음 | B3 명령 결과, 로그의 마지막 30줄 |
| 상태 창에 저장소 오류 안내가 뜸 | 안내 문구 전체(파일 경로 포함) |
| 전환이 너무 느리거나 너무 잦음 | 체감 지연(초), 어떤 창에서 |
| 앱이 멈추거나 오류 | 로그 파일 (`translator.log`) |

로그에는 콘텐츠 이름과 창 제목이 남지 않으므로(프로세스 이름도 기록하지 않음) 그대로 공유해도 사용 기록이 노출되지 않습니다. 단 B3 명령의 결과에는 실행 파일 이름이 나옵니다.

## 되돌리기와 초기화

- **박스를 처음 상태로**: 앱을 끄고 `%LOCALAPPDATA%\MultimodalTranslator\translator.db`, `translator.db-wal`, `translator.db-shm`을 삭제합니다 (저장된 박스가 모두 사라집니다).
- **이전 방식으로 되돌려 다시 시험**: 위처럼 DB를 삭제하고 A1의 `.reg` 파일을 더블클릭해 레지스트리를 복원합니다. 그러면 다음 실행에서 다시 이전(migration)됩니다.
