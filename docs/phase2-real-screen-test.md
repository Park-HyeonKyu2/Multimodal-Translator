# Phase 2 2단계: PaddleOCR 실제 화면 테스트 결과

작성일: 2026-10-12 · 상태: **완료** (동작 확인, 성능은 기록만 함 → 3단계에서 평가)

## 방법

- 스크립트: [`tests/real_screen/paddle_app_check.py`](../tests/real_screen/paddle_app_check.py)
- 실행: `TRANSLATOR_REAL_SCREEN_TESTS=1 TRANSLATOR_PADDLE_OCR_TESTS=1 pytest tests/test_paddle_real_screen.py -s`
- 앱 구성: 실제 앱과 같습니다. MSS 캡처, PaddleOCR(PP-OCRv5 mobile, CPU, oneDNN 끔), 공용 추론 큐, 텍스트 안정화, 말풍선을 쓰고, 번역만 Mock입니다.
  - 조정값은 모두 `tuning.py`의 현재 값을 그대로 씁니다.
- 화면에 띄운 가짜 게임 대사 창:
  - 그라데이션 배경과 흐린 사선 무늬
  - 반투명 대사 패널
  - 화자 이름(18px, 굵게, 노랑)
  - 대사(28px, 검은 외곽선의 흰 글자, Yu Gothic UI)
- 환경: Windows 11, 모니터 2대(각 1920×1080, 배율 100%), Python 3.11.9, paddleocr 3.7.0, paddlepaddle 3.3.1 (CPU)
- 같은 검사를 세 번 실행했고, 결과는 매번 같았습니다(시간 값만 조금씩 다름).

> 직접 그린 가짜 창으로 한 시험입니다. 다음은 **검증하지 않았습니다**.
> - 실제 게임·영상 화면 (장식 글꼴, 움직이는 배경, 반투명 효과, 전체 화면 독점 모드)
> - 모니터마다 배율이 다른 환경

## 동작 결과 (실측)

| # | 시나리오 | 결과 |
| --- | --- | --- |
| 1 | 박스 수동 번역 (일본어 두 줄 + 화자 이름) | 대사 원문 **정확히 일치**(유사도 1.0). 화자 이름은 글자 크기가 달라 따로 묶임. 말풍선이 원문 아래에 놓임 |
| 2 | 타자 효과 (자동 감지, 초당 약 20글자, 56글자) | **부분 번역 0회**, 완성 문장 번역 1회(원문 일치) |
| 3 | 대사 교체 | 새 대사 번역됨. 새 대사를 인식한 뒤 이전 번역이 다시 보인 적 없음 |
| 4 | 원문 이동 (박스 안에서 오른쪽으로 150px) | 말풍선이 148px 따라감. **다시 번역 0회** |
| 5 | 전체 화면 (두 번째 모니터의 안내판) | 안내판 원문 인식·번역됨. 박스 안 대사는 전체 화면 결과에서 빠짐 |
| 6 | 모델을 불러오는 중 종료 | 2.7초에 종료 (모델 로딩과 첫 OCR이 끝나기를 기다림), 프로세스 정상 종료 |

## 시간·부하 기록 (실측, 판정하지 않음)

| 항목 | 값 | 비고 |
| --- | --- | --- |
| 첫 OCR (모델 로딩 포함) | 3.5~3.8초 | 박스 860×170. 모델은 이미 내려받은 상태 |
| 박스 OCR 1회 | 0.29~0.80초 | 글자가 많을수록 늘어남 (인식 단계 비용) |
| 타자 완료 → 번역 도착 | 1.1~2.0초 | Mock 번역 0.3초 포함 |
| 대사 교체 → 번역 도착 | 1.5~1.7초 | |
| 전체 화면 OCR 1회 (3840×1080) | **33~41초** | 텍스트 94~150개. CPU, oneDNN 끔 |
| 전체 화면을 켜고 가만히 있는 10초 | CPU 약 1000% (코어 10개분) | 바탕 화면의 다른 창(시계, 앱 화면 등)이 바뀌어 화면 변화 3회 감지, OCR이 쉬지 않고 이어짐 |

## 발견한 문제와 조치

| 심각도 | 문제 | 조치 |
| --- | --- | --- |
| High (해결) | 긴 OCR(전체 화면)이 실행 중일 때 종료하면 창은 닫히지만 프로세스가 **약 25초** 더 남음. 스레드 풀 정리가 멈출 수 없는 PaddleOCR 추론을 끝까지 기다림 | 종료 대기 시간(3초) 안에 추론이 끝나지 않으면, 설정 저장·로그 기록 뒤 기다리지 않고 프로세스를 끝냄 (`main.finish_process`). 재측정: 출력 뒤 5초 안에 종료 |
| Medium (해결) | 그 추론이 끝난 뒤 이미 삭제된 시그널 객체로 결과를 보내다 `RuntimeError` traceback | 받을 객체가 없으면 결과를 버림 (`_Task._emit`). 회귀 테스트 추가 |
| High (미해결, 3단계) | CPU 전체 화면 OCR이 한 번에 30초 이상 걸리고, 바탕 화면이 조금만 바뀌어도 다시 실행되어 CPU를 계속 씀 | 3단계에서 비교: GPU, oneDNN(paddle 3.2.x), 검출 입력 축소, 모니터·바뀐 부분만 OCR, 전체 화면 확인 간격 |
| High (미해결, 3단계) | 추론 큐 동시 실행 수가 1이고 실행 중인 작업은 멈추지 않으므로, 전체 화면 OCR 중에는 박스 OCR·번역이 최대 수십 초 기다림 | 위와 같음. 전체 화면 OCR 시간을 줄이는 것이 우선이며, 필요하면 번역 전용 자리를 검토 |
| Medium (3단계) | 박스 OCR이 글자 수에 따라 0.3~0.8초. 타자 효과 박스는 그동안 계속 OCR | 3단계에서 지연·CPU 측정 후 간격 조정 |
| Low | `PADDLE_OCR_MIN_SCORE`(0.5)의 효과 미확인. 깨끗한 글꼴이라 점수 미달 사례 없음 | 실제 게임 화면 자료로 확인 |

## 개인정보

- 전체 화면 시나리오는 사용자 바탕 화면 전체를 메모리에서 OCR했습니다.
- 결과에는 검사용 창 텍스트의 일치 여부와 개수·시간만 남겼고, 그 밖의 인식 텍스트와 캡처 이미지는 저장·출력하지 않았습니다.
